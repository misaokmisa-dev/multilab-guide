マイクラMODが起動しない・クラッシュする時の対処法

MODを追加してMinecraftが起動しなくなった場合は、原因を推測して闇雲に入れ直すより、直前の変更点を整理して1つずつ確認します。

事前に確認：MODの対応環境は更新されます。Java版か統合版か、ゲームバージョン、ローダー、配布元の説明を優先してください。

確認する順番

  1. ゲーム本体とMODが対応するバージョンか調べる。
  2. Fabric・NeoForgeなどMODが要求するローダーか確認する。
  3. 必要な依存MOD・APIが不足していないか確かめる。
  4. 最後に追加したMODを一時的に外し、別プロファイルで起動する。
  5. エラーメッセージとクラッシュレポートで原因の候補を探す。
  6. 保存データをバックアップしてから変更を加える。

MOD単体で動くか確認

ゲームがMODなしで起動するかを確認したうえで、必要最小限のMOD構成からテストしましょう。クラッシュログに複数のMOD名が表示された場合は、ローダー・依存関係・競合の情報を配布元で確かめてください。

マルチに参加できない場合

参加者とサーバーでゲームバージョン・ローダー・必要MODが一致しているか確認します。クライアント専用MODとサーバー側でも必要なMODは異なるので、作者の配布情報を優先してください。

どうしても直らない場合

問題のMODの配布ページやIssue欄で同様の不具合報告を探すと、対応版や回避策が見つかる場合があります。バージョンアップ前にバックアップを取り、安定して動く環境を残しておきましょう。

PRMODを友達と遊ぶなら、サーバー側の設定も確認

MOD導入がすべての環境で保証されるわけではありません。ConoHa for GAMEの対応テンプレート・料金・利用条件は公式サイトで確認してください。リンク経由の申込みで当サイトに報酬が発生する場合があります。MOD単体の導入に有料サーバーは必須ではありません。

2026年11月6日時点：ConoHa for GAMEの新規受付は停止中です（公式案内）。別の契約先として、XServer VPS for Gameも仕様比較できます。

ConoHa for GAMEの公式情報を確認 →

参考：Fabric Documentation。当サイトは独立した非公式ガイドです。ゲーム本体・MODやホスティング事業者との公式な関係を示しません。実機・有料サーバーでの動作確認は行っていません。

ゲームは起動するけれど重い場合：FPS低下や数秒ごとのカクつきは、MODが重いときの無料チェックで原因別に確認できます。

起動しない原因を切り分ける：Java版MODの具体的な手順

MODの不具合を調べる際は「どのファイルを入れたら」「どのタイミングで」「どんなエラーが出たか」を分けて記録すると、同じ操作を繰り返さずに済みます。以下はワールドデータを保護しながら、問題の範囲を絞るための手順です。すべてのMODや起動環境に当てはまる万能な修正方法ではありません。

1. まずワールドと設定を保護する

起動に失敗したからといって、savesフォルダを削除する必要はありません。ゲームを終了し、Minecraftランチャーで指定しているゲームディレクトリを確認します。通常のWindows環境の例は%appdata%\.minecraftですが、別のプロファイルやランチャーでは場所が違う場合があります。対象のsavesフォルダと、必要な設定・MOD構成のコピーを別の場所に作成してから作業します。

2. ローダー・MOD・ゲーム本体の組み合わせをそろえる

たとえばMODの配布ページに「Minecraft Java 1.21.x／Fabric」と書かれているなら、ゲーム本体のバージョン、Fabricのバージョン、MODファイルの対応条件を確認します。NeoForge向けやForge向けファイルは、名前が同じMODでもFabric環境でそのまま使えるとは限りません。依存ライブラリ（Fabric APIなど）が必要な場合は、作者が指定した対応版を入れます。

3. 最小構成で起動して原因の候補を減らす

  1. 新しい起動プロファイルまたは別のゲームディレクトリに、対象ゲーム版とローダーだけを用意して起動します。
  2. 問題のMODと必須の依存ファイルだけを追加し、まずは新規ワールドやタイトル画面まで起動できるか確認します。
  3. 最小構成では動く場合、元のMOD構成にある競合・重複・設定差を疑い、追加するMODを少しずつ増やして比較します。
  4. 起動に失敗する組み合わせが見つかったら、MODの配布元で既知の不具合・互換性・更新履歴を確認します。既存ワールドをいきなり開いたり、バックアップなしでMODを削除したりしないでください。

4. ログを見る場所と読み方

Java版の代表的なログはlogs/latest.log、クラッシュ時に保存されるレポートはcrash-reportsにあります。ただしログの末尾に出たMOD名が必ず根本原因とは限りません。「不足している依存MOD」「対応していないゲーム版」「クラスを読み込めない」などの文言と、発生前後の変更内容を照合します。ログに表示されたエラーをそのまま検索する際は、ユーザー名、PC内のフォルダ名、サーバーIP、接続情報などの個人情報が含まれていないか必ず確認してください。

5. 症状ごとに次に見るべき項目を変える

起動前に落ちる：ローダー／ゲーム版／依存MODを優先。ワールドを開く瞬間に落ちる：ワールドとMOD構成の一致、追加・削除したMOD、バックアップからの切り分けを優先。ゲームは起動するが重い：クラッシュ対処ではなく、FPS・メモリ・サーバー遅延のどれかを重さの原因別チェックで確認してください。

参考：Fabric公式「Crash Reports」、Fabric公式「Installing Mods」。本ページはトラブルシューティングの一般的な手順を整理した非公式ガイドです。特定環境での実機検証・修復結果を保証するものではありません。

エラーログを確認したら、無料のクラッシュログ診断で原因候補と確認順を調べられます。ログの送信は不要です。
